# Data definitions and provenance

## Two valid definitions

The original-package snapshot and reconstructed definitions are both valid
scientific assets. They differ in source inputs, coverage and processing rules.
Neither automatically replaces the other, and their results need not coincide.

A legacy label does not establish obsolescence. Trace the actual inputs and
select a definition for its suitability to the scientific question. The public
code does not include every implementation or input used by every research branch.

## Comparison and combination

Record source identity, code and configuration provenance, geographic and temporal
coverage, sample filters, units, aggregation grain and accounting boundaries.
Before combining results, specify the common sample and transformations. Preserve
both source results and explain any portions that cannot be aligned.

Do not silently substitute definitions or compare totals with different coverage.
The load-baseline and WFH-increment engines are model components; current and
future PV are scenarios. Those distinctions are separate from data definitions.

## Private asset configuration

Public source uses logical identifiers. Storage locations and their organization
are supplied privately by the operator and are not part of this publication.
Source identity and content hashes can document provenance without publishing
machine-specific locations. No further asset cleanup is pending.
