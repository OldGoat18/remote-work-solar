# Repository instructions

Read README.md and CONFIGURATION.md before changing analysis code.

- Both the original-package snapshot and reconstructed definitions are valid
  project assets. Select by scientific purpose and record provenance and alignment.
- Do not publish storage layouts, data-location examples, machine-specific
  locations or the values of private asset bindings in code, configuration,
  documentation, comments, logs or generated reports.
- Published code uses logical binding identifiers. The operator supplies their
  values through WLPR_ASSET_CONFIG; never add private defaults or encoded copies.
- Use functional source names and retain scientific dates, model specifications,
  random seeds and dependency requirements.
- Preserve the publication allowlist. Do not include research datasets,
  manuscripts, figures, private profiles or generated results.
- No further cleanup is pending. Protect intermediate assets and environments.
- Verify syntax, binding coverage and affected computations in a disposable
  workspace. Never launch full experiments merely to check documentation.
